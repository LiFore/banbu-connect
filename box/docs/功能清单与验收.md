# 功能清单与验收标准

版本：0.1 | 日期：2026-10-28 | 依据：`管理面板_开发评估.md`

约定：
- **编号** `模块-序号`，与开发评估的 M1–M13 对应。提交信息和 PR 标题中引用编号。
- **优先级** P0 = 试点必需；P1 = 试点期间补齐；P2 = 试点之后。
- **验收**：每条都必须能用自动化测试或明确的手工步骤判定通过或不通过。标 🔬 的条目必须在实机（N100 + iStoreOS，ADR-029；原为 ImmortalWrt + Nikki）上验收。
- 通用要求（所有条目都适用，不再逐条重复）：API 错误返回统一结构 `{code, message, detail}`；日志、诊断包和 API 响应中不出现明文凭据；涉及配置变更的操作都要生成配置版本。

## M9 guard 核心 🔬

| 编号 | 功能点 | 验收标准 | 优先级 |
|---|---|---|---|
| M9-01 | 独立的 nft 表 `inet proxy_guard`，包含 forward 和 output 两个基础链 | `fw4 reload` / `fw4 restart` 之后表仍然存在 | P0 |
| M9-02 | 启动早期加载上一份已知可用的策略 | 冷启动过程中持续抓包，在 guard 规则加载之前没有任何 LAN→WAN 境外流量被转发 | P0 |
| M9-03 | 模式 B 规则：严格目标 > 国内/白名单放行 > 其余 LAN→WAN 丢弃 | 从 LAN 直连一个境外 IP 会被丢弃；访问国内 IP 正常；严格集合中的 IP 即使属于国内也会被丢弃 | P0 |
| M9-04 | output 链：Mihomo 出站只允许去代理节点地址、国内 IP、白名单；放行 NTP | Mihomo 的 DIRECT 规则访问未同步的境外 IP 会被丢弃；NTP 校时正常 | P0 |
| M9-05 | 健康状态机：检查间隔、失败阈值、恢复阈值可配；切换过程中保持阻断 | 健康状态来回翻转测试（每 10 秒 kill 一次 Mihomo，持续 10 分钟）期间，境外直连泄漏为 0 | P0 |
| M9-06 | 状态切换时清理相关 conntrack；禁用 flow offload | 状态切换后，之前已建立的境外直连连接被断开 | P0 |
| M9-07 | fw4 reload 后自检，缺失时自动恢复 | 手动 `nft delete table inet proxy_guard` 后 5 秒内恢复，并记录事件 | P0 |
| M9-08 | IPv6 forward 一律丢弃，LAN 不下发 IPv6 地址 | LAN 客户端拿不到 IPv6 地址；手工配置 IPv6 后也无法转发出去 | P0 |
| M9-09 | 保留管理面访问 | 在任何状态下，LAN 都能访问面板、SSH、DHCP 和 DNS | P0 |
| M9-10 | 故障注入套件全部通过 | Mihomo 重启、Mihomo 崩溃、Nikki 停止、fw4 reload、冷启动、DNS 绕过（客户端自定义 DNS 和 DoH）、UDP/QUIC，每项都要求境外泄漏为 0 | P0 |
