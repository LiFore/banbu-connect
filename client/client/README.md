# Banbu Connect（桌面客户端）

班布（Banbu）的桌面客户端：本机代理加 Kill Switch，不依赖 Clash Verge。自用，支持 macOS 和 Windows。

在家里的受信 Wi-Fi 上，代理交给路由盒，本机直连；离开受信 Wi-Fi，Claude、ChatGPT 必须经本机内核，内核不可用就断开（见「受信网络」）。

内部命令是 `boxctl desktop`；系统服务、安装目录和数据目录都叫 Banbu Connect。路由盒（`../box`）和这里各自维护一份共用的代理代码（订阅、节点、代理组、配置生成）。

```
client/app（Tauri）        托盘、窗口、首次安装时提权
   │ HTTP + 令牌（127.0.0.1:17930）
boxctl desktop（系统服务）  管理员权限，开机自启
   ├─ 订阅、节点、代理组    后端和页面与路由盒同款
   ├─ internal/gen         数据变化后自动生成配置并热重载
   ├─ boxctl mihomo        内核子进程，编进同一个二进制
   ├─ internal/killswitch  只保护特定服务的 Kill Switch，按网络选择路径
   └─ internal/trust       受信网络：识别 Wi-Fi、探测出口、阻断入口
```

| 目录 | 作用 |
|---|---|
| `client/app/` | Tauri 外壳：托盘菜单、窗口、安装页 |
| `boxctl/internal/desktop/` | 后台服务：内核运行、默认代理组、系统服务安装 |
| `boxctl/internal/gen/` | Mihomo 配置生成器 |
| `boxctl/internal/killswitch/` | Kill Switch：NRPT/防火墙（Windows）、`/etc/resolver`/pf（macOS） |
| `boxctl/internal/trust/` | 受信网络：Wi-Fi 识别、出口探测、出口基准、阻断入口（REFUSED） |
| `web/src/pages/desktop/` | 概览、线路、Kill Switch、规则与设置页面 |
| `client/guard/`、`client/clash-verge/` | 旧方案（脚本版 Kill Switch、Clash Verge 脚本），客户端验证通过后可以删除 |

## 构建

需要 Go ≥ 1.26、Node ≥ 20、Rust。在目标平台上运行（Tauri 不能交叉编译）：

```bash
./scripts/build-app.sh          # 沿用 tauri.conf.json 里的版本
./scripts/build-app.sh 0.2.4    # 先把版本号写进 tauri.conf.json 和 Cargo.toml，再打包
```

产物在 `client/app/src-tauri/target/release/bundle/`。OTA 只认更高的版本，发布新包前要升版本号。

**macOS 签名：** 没有 Apple 开发者证书，`tauri.macos.conf.json` 用 `signingIdentity: "-"` 给整个 .app 做 ad-hoc 签名（不做的话只有链接器给主程序的签名，下载后系统会报「已损坏」）。ad-hoc 签名过不了 Gatekeeper，第一次打开需要二选一：在「系统设置 → 隐私与安全性」里点「仍要打开」，或执行 `xattr -dr com.apple.quarantine "/Applications/Banbu Connect.app"`。要双击直接打开，需要 Developer ID 证书签名并公证。

自己编译 `boxctl` 时要带 `-tags with_gvisor`，否则 TUN 启动失败（概览页会显示原因）。

## 第一次使用

**先清理旧方案，否则会冲突：**

- **退出 Clash Verge：** 它的 TUN 和 DNS 端口会和这里冲突。
- **卸载上一版程序（如果装过）：** `sudo /usr/local/libexec/killswitch uninstall`。它和新服务用同一个端口和同一套规则。
- **卸载改名前的服务（如果装过）：** Boxctl 代理服务 `sudo /usr/local/libexec/boxctl desktop uninstall`，Boxctl Gate `sudo /usr/local/libexec/boxctl-gate uninstall`（Windows 分别是 `"C:\Program Files\boxctl\boxctl.exe" desktop uninstall` 和 `"C:\Program Files\boxctl-gate\boxctl.exe" uninstall`）。安装时检测到它们会拒绝。
- **脚本版 Kill Switch 不用手动卸载：** 新服务在保护关闭时会清理它写的规则。

然后：

1. 打开应用，按提示安装后台服务（系统会弹出授权）。
2. 在「订阅」导入机场，或在「节点」手动添加。
3. 在「概览」打开代理。第一次要下载 geo 数据，等待时间较长。
4. 在「线路」为 Claude、ChatGPT 选好线路。ISP 节点在「节点」添加（用 curl 模式导入），再加进这些组。
5. 确认能正常访问后，打开 Kill Switch。
6. 在家里的 Wi-Fi 上，到「概览 → 当前网络」点「信任当前 Wi-Fi」。出口探测成功后直连放行，并记住这个出口。

卸载：`sudo /usr/local/libexec/banbu-connect desktop uninstall`（Windows 用管理员终端运行 `"C:\Program Files\Banbu Connect\banbu-connect.exe" desktop uninstall`）。数据保留在 `/Library/Application Support/Banbu Connect`（Windows：`C:\ProgramData\Banbu Connect`）。

修复：后台服务起不来时，Kill Switch 和 DNS 防泄漏的规则会留在系统里，受保护的服务乃至整机 DNS 不通。点托盘图标打开窗口，在安装页点「打开修复工具」，二次确认后清除这些规则和指向本机的系统代理（`desktop repair`，需要管理员授权）。服务恢复后会按设置重新安装规则。

## 规则如何生成

配置由 `internal/gen` 从数据库生成，用户不直接编辑 YAML。任何修改保存后都会自动生成；校验通过才热重载，失败时内核继续使用上一份配置，错误显示在概览页。规则从上到下依次是：

1. 自定义规则（「规则与设置」）。
2. 受保护服务的规则：每个域名后缀自动生成 QUIC 阻断和严格规则，指向所选的严格代理组。
3. OpenAI、Claude 规则集。
4. 内置的直连和代理规则集（目标组被删除时自动跳过）。
5. `MATCH,漏网之鱼`，默认直连。

受保护服务的代理组必须标记为「严格」，否则拒绝生成。这样在 Kill Switch 页面加域名就够了，不用再同步规则。

## DNS 接管

- **系统 DNS：** 开启 TUN 后，系统查询交给内核（`dns-mode: hijack`）。Windows 还用 `strict-route` 拦截物理网卡上的 53 端口；Kill Switch 启用时要关闭它（V22），界面会提示。
- **内核的上游：** 境外域名经「代理模式」组查询 Cloudflare。`geosite:cn` 和节点域名仍直连国内 DNS，这是有意的：节点域名解析不能依赖节点。代价是节点全部不可用时，国内列表之外的域名解不出来；「代理模式」选直连或使用直连模式时，上游也直连。
- **不开 TUN：** 只有经代理端口的流量由内核解析，其他应用仍用系统 DNS。
- **DNS 防泄漏（默认开启，概览里可关）：** TUN 接管时，在物理网卡上拦截发往 53、853 端口的流量（macOS 用单独的 pf 锚点 `com.apple/boxguard-dns`，Windows 用防火墙分组 `boxguard-dns`）。这样路由器 DNS、局域网 DNS、IPv6 链路本地 DNS、macOS 指定网卡的查询、Windows 关闭 strict-route 后的并行查询都出不去，系统查询只能经 TUN。内核的上游全是 443/853 加 IP 且经代理组，`default-nameserver` 也改成了 DoH，不受影响。
  - 只在 TUN 接管时生效；TUN 掉了或内核退出立即撤销，否则整机无法解析域名。规则不持久，服务启动时先清掉上次崩溃可能留下的。
  - 代价：TUN 接管期间，强制门户（酒店、机场的认证页）、公司内网域名、路由器的管理域名解析不了。遇到时在概览里关掉，或先关 TUN。
  - 管不到：浏览器自带的安全 DNS（Chrome/Edge 自定义 DoH、Safari 专用代理）用自己的解析商，测试时请关掉；「代理模式」组选了直连时，境外查询从本机出口发出。
- **geo 数据：** 内核需要 GeoIP.dat、GeoSite.dat。国内直连 jsDelivr 常失败，所以安装包里自带一份（`scripts/build-app.sh` 下载），安装服务时放进内核目录；仍缺时服务依次尝试多个镜像，代理运行时再经代理下载。规则集下载经「代理模式」组。

## 管理服务与配置下发

管理服务（`boxctl server`）在同级仓库 `../server`，部署方法见那边的文档。它在网页上维护订阅、节点、代理组、线路和规则，发布给绑定的客户端，并托管客户端更新包。

**接入（申请授权）：** 客户端默认连接 `https://connect.duallee.cn`，可以改。用户在引导屏或「服务端」页填好设备名称（默认取电脑名称）后点「申请接入」，客户端把设备名称、平台（如 `darwin/arm64`）、系统版本、应用版本提交给管理服务（`internal/dist/enroll.go`）。管理员在「客户端」页的「接入申请」里授权（可以改名）或拒绝；用户点「刷新授权」后，客户端用申请时拿到的密钥领取令牌并自动绑定。

- 令牌在领取时才生成，服务端只存哈希，只能领取一次。领取后没绑定成功的（比如服务端还没发布配置），令牌留在本机 `enroll.json`，下次刷新时重试。
- 同一台电脑重复申请时合并成一条（按安装时生成的随机 ID，存在 `install_id`，解绑后保留），旧密钥失效。重新授权已吊销的客户端会解除吊销。
- 申请接口不需要登录：每个 IP 最多 5 条、全部最多 200 条待授权的申请，超出返回 429。
- 手动输入令牌的方式保留，在申请页点「已有令牌，手动绑定」。

初始管理员密码在数据目录的 `initial-password`，首次登录要修改；忘记时运行 `boxctl reset-password -data-dir …`。

**预置配置：** 首次启动前把文件放进数据目录的 `seed/`，服务在还没有任何节点和代理组时导入一次（`internal/dist/seed.go`）。`*.yaml` 是 Mihomo 配置，导入其中的 `proxies`（含 `dialer-proxy`）和 `proxy-groups`；`*.txt` 每行一条规则，作为下发规则。同名节点、组以文件名排序靠前的为准。`Claude`、`ChatGPT` 组标记为严格组，成员里能走到 DIRECT 的组（如「代理模式」）换成它除 DIRECT 以外的成员。导入失败时清空已导入的内容，下次启动重试。`boxctl server export-seed -data-dir … -out …` 把一台管理服务当前的配置导出成预置文件（含严格组 `x-strict` 和线路 `x-selections`）。文件含节点凭据，不要放进仓库；导入后可以删掉。

| 管理页面 | 作用 |
|---|---|
| 订阅、节点、代理组 | 与路由盒面板相同 |
| 线路与规则 | 每个手动选择组的默认成员；放在客户端自定义规则之前的规则 |
| 发布 | 把当前的节点、代理组、线路、规则发布成新版本（加密保存，含凭据） |
| 客户端 | 新建客户端令牌（只显示一次）、吊销；名称和系统版本由客户端连接时上报（旧版客户端不上报，保留原名称）；查看版本、同步到第几版、最近联系 |
| 客户端更新 | 上传更新包和签名，打开「发布」后客户端才会收到；「灰度」指定客户端后只有它们收到这个版本，其他客户端收到不在灰度中的最高版本，清空即全量 |
| Claude 账号 | 登记账号邮箱（它自己的 Gmail），授权 Gmail 只读，指定哪些客户端可以用；见下面「Claude 账号登录」 |

**客户端：** 在「高级 → 管理服务」填地址、令牌（自签名证书再填指纹）后绑定，每 5 分钟同步一次。

- **服务端为准：** 下发的节点、代理组、规则与「高级」里的本地配置合并，同名时以下发的为准。
- **线路：** 每个新版本只在第一次收到时切换一次，之后在「线路」里手动切换的结果不会被覆盖。
- **同步失败：** 继续使用上一次的配置，概览上提示。令牌被吊销同样如此，要停止使用请在客户端解除绑定。
- **解除绑定：** 移除下发的配置，回到本地配置。
- **Kill Switch、受信网络、DNS 防泄漏：** 这些设置都只在本机，不下发。

## Claude 账号登录

绑定管理服务后，概览上的「Claude 账号」列出允许本机使用的账号，点「登录」在本机发起 Claude Code（CLI）的 OAuth 登录。我们只发起，不接管：PKCE、换 token、保存凭据都由 Claude Code 自己完成。

1. 页面通知本机服务，本机服务请管理服务开始等这个账号的登录邮件（`internal/dist/claude_client.go`）。
2. 托盘外壳从状态里看到待启动的登录，执行 `claude auth login --claudeai --email <邮箱>`（`client/app/src-tauri/src/claude_login.rs`）。必须由外壳执行：后台服务以 SYSTEM/root 运行，由它执行的话凭据会写到管理员的目录。
3. 管理服务用 Gmail API 每 5 秒搜一次这个账号的 Gmail（ADR-025，`internal/dist/gmail.go`）：`from:mail.anthropic.com after:<发起时间>`，取最新一封的原文，核对发件人后取出 `https://claude.ai/magic-link#…`（`internal/dist/claude.go`）。

**Gmail 授权：** 管理服务保存一个 Google OAuth 客户端（「桌面应用」类型，密钥加密保存），每个账号授权一次只读权限（`gmail.readonly`），服务端只保存 refresh token（加密），不保存 Gmail 密码。授权时浏览器会跳到打不开的 `http://127.0.0.1:53682/?…`，把这个地址粘贴回管理页面即可；这样管理服务没有域名、用自签名证书也能授权。OAuth 同意屏幕要发布为正式版，停在「测试」状态时授权 7 天后失效。授权失效或被撤销时，登录立即失败并提示重新授权。
4. 本机服务取到链接后先留在本机（阶段 `mail_ready`），概览自动打开这个账号的「邮件」。用户在登录邮件里点「在浏览器打开」后，外壳的长轮询才拿到链接，用默认浏览器打开；浏览器里完成授权后 Claude Code 收到回调并保存凭据。浏览器已登录同一账号时不会发邮件，Claude Code 直接完成。
5. 外壳用 `claude auth status --json` 核对登录的邮箱，回报给管理服务，「Claude 账号」页显示最近登录的时间和客户端。

- **查看邮件：** 每个账号旁的「邮件」列出这个 Gmail 最近 7 天 Anthropic（`anthropic.com` 及子域名）发来的邮件，最多 10 封（`internal/dist/claude_mail.go`），不要求先点「登录」：自己手动登录（在浏览器或 Claude Code 里输入邮箱）时也在这里取登录链接，可以复制，或点「在浏览器打开」由托盘外壳打开（几秒内）。其他发件人的邮件不会离开管理服务；正文只返回纯文本，客户端不渲染邮件的 HTML。
- **链接等于登录凭据：** 一键登录的链接管理服务只在内存里保留，只交给发起登录的那台客户端一次，10 分钟内没收到邮件就作废，不入库、不写日志。但「邮件」里能看到原文，所以被允许使用这个账号的客户端在 7 天内都能看到登录链接。外壳只打开 `https://claude.ai/magic-link#` 开头的链接，页面请求打开时本机服务和外壳各校验一次。
- **每台设备各自登录：** 不在设备之间复制凭据，避免一台刷新令牌后另一台失效。
- **找 claude：** 外壳先找 PATH，再找 `~/.local/bin`、`%APPDATA%\npm`、Homebrew 等常见位置。找不到时登录失败并提示安装 Claude Code。

## 应用更新（OTA）

- **签名：** 更新包用 Tauri updater 签名。私钥在构建机的 `~/.tauri/banbu-connect.key`（不进仓库，丢了只能换公钥重新发完整安装包），公钥在 `tauri.conf.json`。`scripts/build-app.sh` 找到私钥才生成更新包，结束时列出要上传的文件：macOS `Banbu Connect.app.tar.gz`，Windows `*-setup.exe`，各带一个 `.sig`。
- **发布：** 在管理服务「客户端更新」上传文件和 `.sig`，填版本号（与 `tauri.conf.json` 一致）和平台，打开「发布」。
- **检查：** 外壳启动时和每次打开主界面时各检查一次（一分钟内不重复），在后台时每小时一次，托盘菜单可以手动检查；有更新时托盘显示「安装更新 x.y.z」，点击后下载、安装、重启。
- **转发：** 外壳只访问本机服务 `http://127.0.0.1:17930/api/v1/desktop/update/…`，由服务带着客户端令牌转发到管理服务。所以外壳拿不到服务端令牌，也不用处理自签名证书。更新包由签名保证完整，回环地址上用 http 是安全的。
- **后台服务：** 应用更新后，打包在里面的后台服务是新的，但已安装的还是旧版本。外壳发现两者版本不同时打开安装页，提示「更新后台服务」，授权一次即可；设置和数据保留。

## 受信网络

Kill Switch 启用后，受保护的服务按网络走三条路之一（`internal/killswitch/path.go`）：

| 路径 | 条件 | 系统规则 |
|---|---|---|
| 经本机内核 | 没有设置受信 Wi-Fi；不在受信 Wi-Fi 上；或 TUN 已接管流量 | 原 Kill Switch：DNS 交给 Mihomo，网段在物理网卡上拦截。内核不可用时断开 |
| 直连（路由盒） | 默认路由走受信 Wi-Fi，出口探测成功，出口 IP、地区符合要求 | 不写规则 |
| 阻断 | 在受信 Wi-Fi 上，但出口还没确认、探测连续失败、出口变化或地区不符 | DNS 交给阻断入口（一律回答 REFUSED），网段在物理网卡上拦截 |

- **出口要求：** 设了「允许的出口 IP」就按列表；没设时，每个 Wi-Fi 第一次探测到的出口记为基准，之后不一致就阻断，在概览点「接受新出口」后恢复。
- **出口探测：** 默认请求 `https://chatgpt.com/cdn-cgi/trace`，看到的是受保护服务那一侧的出口。ChatGPT 没有 IP 层规则，阻断期间仍能探测；`claude.ai` 在 Claude 的网段里，不能作为唯一的探测地址。探测自己解析域名、不走系统代理。直连时每 30 秒探测一次，阻断或失败后每 10 秒一次，连续两次失败就阻断。探测在后台进行，不挡住每 3 秒一次的网络检查；探测期间换了网络，旧结果直接丢弃。
- **网络检查：** 每 3 秒看一次默认路由所在的网卡和 SSID。macOS 用 `ipconfig getsummary`；Windows 用 WLAN API（`wlanapi.dll`，不起进程），用不了时退回 `netsh wlan show interfaces`。
- **严格线路：** 每 30 秒（阻断时 10 秒）经每个严格组探测出口。内核换了配置、在「线路」里切换了任何组、管理服务下发的线路生效后，旧结果作废并立即重测；下发了允许的出口时，重测完成前按「正在探测」阻断（通常一两秒）。网络变化时也立即重测，但不作废结果。
- **系统通知：** 保护启用时，托盘外壳弹出三类通知：已阻断受保护的服务、已恢复访问、出口探测失败（从成功变为失败时一次）。出口确认、内核重启这类「正在探测」的短暂阻断持续 15 秒以上才通知；出口不符合、探测失败等确定的阻断立即通知。
- **TUN 优先：** TUN 接管时探测会经过内核，看到的是节点的出口，所以不探测，总是经本机内核。TUN 关闭后要重新确认出口才直连。
- **换路时：** 网络变化、TUN 开关都会让旧的探测结果作废；每次换路清一次系统 DNS 缓存。服务启动时先按「经本机内核」写规则，确认出口后才直连。
- **阻断入口：** macOS `127.0.0.1:10053`，Windows `127.0.0.3:53`（`127.0.0.2:53` 已给 Mihomo）。服务不在时端口关闭，解析同样失败。
- **限制：** 直连状态下没有系统规则，服务崩溃到被拉起之间不会因网络变化而阻断。ChatGPT 已建立的连接在出口变化后不会立即断开（没有 IP 层）。插着网线且网线是默认路由时按「不在受信 Wi-Fi」处理。

## Kill Switch 原理

未知流量继续直连，只保护指定的服务。

- **DNS 层：** 受保护的后缀只交给 Mihomo 解析；内核不在时解析失败。不使用 fake-ip（ADR-014），应用拿到的是真实 IP，所以内核故障后，缓存的 IP 在有效期内可能直连。服务检测到故障时会清系统 DNS 缓存，应用自身的缓存清不掉，这部分靠 IP 层兜底。
- **IP 层：** 在物理网卡上拦截固定网段，兜底 DoH 和硬编码 IP。ChatGPT 共用 Cloudflare，没有这一层，只做到尽力而为。
- **规则写在系统里：** 服务退出或崩溃不会撤销保护，只有关闭保护或卸载才会撤销。服务每 30 秒核对一次，规则被删或接入新网卡时自动恢复。

| 状态 | 含义 |
|---|---|
| 未启用 | 没有写入任何规则 |
| 保护中 | 规则生效，流量经 TUN 走内核 |
| 保护中，TUN 未接管 | 只有走系统代理的应用能访问受保护的服务 |
| 已断开受保护的服务 | 内核不可用，Kill Switch 正在起作用，恢复后自动清 DNS 缓存 |
| 受信网络，直连放行 | 在受信 Wi-Fi 上且出口符合要求，没有写规则 |
| 已阻断 | 在受信 Wi-Fi 上，但出口没确认或不符合要求 |
| 保护可能不完整 | 规则写入失败，看界面上的错误 |

## 诊断数据上报

绑定管理服务后，客户端把排查连接问题需要的数据随同步上报（`internal/desktop/diag.go`、`internal/dist/diagnostics.go`），管理员在「客户端」页面点「诊断数据」查看。用户可以在客户端「服务端」页面关闭，关闭后不再收集，本机未上报的也清掉；那里也能看到待上报的全部内容。

- **上报：** 出口探测结果（受信 Wi-Fi 和每个严格组的 IP、地区、耗时、错误；结果变了就记，没变时每 15 分钟一条，带上期间的探测和失败次数）、Kill Switch 状态变化、代理内核意外退出、配置应用失败、TUN 启动失败、Mihomo DNS 和 TUN 接管的故障与恢复、网络类型变化（网卡、是否 Wi-Fi、是否受信、能否读到名称），以及每次上报时的状态快照。
- **不上报：** 访问的域名和连接、流量、Wi-Fi 名称（原因文字里的也去掉）、开关机和休眠、服务或应用的启动退出、开关代理、切换模式和线路等操作。服务启动后第一次观察只记下状态不记事件；内核健康只在内核预期运行时才记，用户自己停掉代理不记。
- **时机：** 每 5 分钟上报一次，出现警告或错误后 30 秒内上报。上报不出去时本机保留最近 1000 条（`diagnostics.json`），成功后删除。
- **服务端：** 按客户端生成的序号去重，保留 30 天、每台最多 5000 条，删除客户端时一并删除。

## 安全

后台服务以管理员权限运行，所以：

- 只监听回环地址，并校验 Host，防止恶意网页用 DNS 重绑定访问。
- API 只认 Bearer 令牌，跨站页面无法附带；令牌保存在只有本人可读的用户目录。
- 外壳打开窗口时把令牌放在 URL 片段里（不会发给服务器），页面读取后立即从地址栏移除。
- 服务从普通用户写不了的目录运行；节点凭据加密入库，生成的配置文件权限为 `0600`。
- 后台服务的网页只有拖动、最小化、最大化、关闭窗口这几个 Tauri 权限（自绘标题栏用），外加四个外壳命令：打开完整界面（`shell_open_full`，可带站内路径）、回到精简界面（`shell_open_compact`）、列出在运行的 AI 应用（`shell_running_apps`，退出确认框用，只返回应用名）和退出应用（`shell_quit`，可先让服务暂停代理），见 `capabilities/titlebar.json`。自定义命令在 `build.rs` 的应用清单里登记、按能力逐个授权，安装、修复等命令只有本地页面（安装页、托盘面板）能调用。
- **退出与卸载：** 「退出」只让后台服务暂停内核（不改设置，服务保留），下次打开应用或开机时恢复，不用重新安装、不用提权；卸载在「高级 · 卸载」，由服务在独立进程里停止并删除自己、撤销保护规则，数据保留。
- 管理服务的客户端令牌只存 SHA-256；发布的配置加密保存。客户端把绑定信息和下发的配置存在数据目录（只有管理员可读）。

## 开发

不改动系统地预览（Kill Switch 用假后端，内核是真实的；要在设置里关掉 TUN）：

```bash
cd boxctl && go run ./cmd/boxctl desktop run -fake -fake-ssid Home -addr 127.0.0.1:17933 -data ../.dev/desktop
```

本地管理服务在 `../server` 里运行（见那边的说明），绑定时填它「客户端」页面显示的指纹。

`-fake-ssid` 把当前网络当作这个 Wi-Fi，用来预览受信网络（出口探测是真实的，阻断入口用 `127.0.0.1:10054`）；不加时读取真实的 Wi-Fi。
